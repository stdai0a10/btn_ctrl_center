# 前端 PWA 升級：現況與實作規劃

> 狀態：產品決策已於 2026-10-28 分輪確認；圖示草案已製作。PWA 功能尚未實作，實際 HTTPS 環境資訊與三平台驗收結果待執行階段取得。

## 目標與範圍

讓一般使用者能把 Button Control Center 安裝到裝置主畫面，從主畫面進入 `/buttons`，並在斷線時得到清楚的狀態。設備控制和帳號資料仍由伺服器即時授權與處理。第一階段交付可安裝性、離線提示、安全的快取邊界；完整離線瀏覽、離線編輯、背景同步與推播另行設計。`/manage` 不列入 PWA 使用體驗或驗收範圍。

## 現況盤點（2026-10-28，`dev` 工作樹的靜態檢查）

| 面向 | 現況 | PWA 影響 |
| --- | --- | --- |
| 前端 | Laravel 12 + Inertia React 3 + Vite 7；`resources/js/app.jsx` 動態載入頁面，`resources/views/app.blade.php` 是 HTML 入口 | 可沿用現有入口，不需改為純 SPA |
| 建置 | `vite.config.js` 使用 `laravel-vite-plugin`，產物在 `public/build`；Docker Node 階段執行 `npm install && npm run build` | 根目錄的 manifest、圖示、Service Worker 和離線頁放在 `public/`，由 Nginx 直接服務 |
| 路由 | `/buttons`、`/rooms`、帳號頁需登入；`/manage` 是同一來源的管理後台 | Service Worker 的 `/` scope 會涵蓋管理頁，快取規則必須保守 |
| 資料 | 按鈕、房間和管理頁由 `/api/*`、`/manage/api/*` 即時載入；Inertia 首次載入為 HTML，站內切換可收到含使用者 props 的回應 | 不快取 HTML、Inertia 回應或 API 回應，避免舊權限或跨帳號資料外洩 |
| 操作 | `/api/button-actions` POST 建立設備任務，前端每 2 秒查詢執行狀態；POST 帶 `request_id` | 斷線時不能排隊或顯示執行成功；送出後失去回應須提示結果待確認 |
| 現有 PWA | 原本的 `public/favicon.ico` 為 0 位元組；目前已先製作 `public/icons/` 下的圖示草案，但仍沒有 manifest、Service Worker、離線頁或安裝流程 | 圖示可接入；其餘資產與註冊程式待實作 |
| 開發與部署 | Compose 對外 `8080:80`，範例 `APP_URL=http://localhost`；正式 TLS 入口未在本工作樹確認 | localhost 可測；其他主機須 HTTPS 並以實際部署環境驗證 |
| 測試 | `package.json` 僅有 `dev`、`build`；PHP feature tests 會停用 Vite | 需補直接驗證 Service Worker 行為的測試與真實瀏覽器驗收 |

依據：`package.json`、`vite.config.js`、`resources/views/app.blade.php`、`resources/js/app.jsx`、`resources/js/bootstrap.js`、`resources/js/pages/Buttons/Index.jsx`、`routes/web.php`、`routes/api.php`、`routes/manage.php`、`nginx.d/default.conf`、`docker/Dockerfile`、`docker/docker-compose.yml`。

## 路線選擇

| 路線 | 交付 | 代價與風險 |
| --- | --- | --- |
| A. 只提供安裝中繼資料 | manifest、圖示、獨立視窗 | 最快，但斷線時只有瀏覽器錯誤頁 |
| **B. 安裝 + 安全離線提示（已選）** | A 加 Service Worker、靜態離線頁、操作失敗提示 | 少量前端與瀏覽器測試；使用者資料仍須在線取得 |
| C. 完整離線操作 | 快取個人按鈕、離線編輯或排隊指令 | 必須設計使用者隔離、登出清除、衝突解決、權限過期和指令重送；目前不適合直接與安裝功能綁在一起 |

採路線 B。`start_url` 為 `/buttons`，未登入時沿用既有登入導向；`scope` 為 `/`，因一般使用者路徑分散在根目錄。這個 scope 在瀏覽器層也涵蓋 `/manage`，但 Service Worker 對管理後台請求完全直通，不快取、不顯示離線備援頁，也不提供安裝引導；使用者接受已安裝視窗仍可能開啟管理頁。

## 第一階段行為契約

1. 可安裝：提供 `public/manifest.webmanifest`，包含 `id`、`name: Button Control Center`、`start_url: /buttons`、`scope: /`、`display: standalone`、`theme_color: #256c68`、`background_color`、繁體中文語系和 192、512 PNG 圖示；`app.blade.php` 連結 manifest、theme color 及 Apple touch icon。使用已製作的 `public/icons/pwa-icon.svg`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png`，不使用空白 favicon。
2. Service Worker：`public/sw.js` 以根路徑註冊，只預存自給自足的 `public/offline.html`；只有一般使用者頁面的文件導覽在網路請求失敗時回傳離線頁。`/manage`、`/manage/*`、API、認證與 Inertia XHR 全部直通網路。HTTP 401、403、404、500 等伺服器回應照原樣傳回。
3. 不存使用者資料：所有 API、Inertia XHR、HTML 導覽、POST/PUT/PATCH/DELETE、管理後台與認證回應都不加入 Cache Storage；不做 Background Sync。離線頁不能顯示先前帳號、房間、設備或控制結果。唯一允許短期持久保存的是待確認控制請求的 `request_id`、使用者 `public_id` 與建立時間，不含按鈕、房間或設備資料；確認結果、登出或逾期時清除。
4. 開啟中的按鈕頁：斷線時保留已顯示的資料，標示可能過期並停用控制與其他需送出的修改。若送出控制指令後連線中斷，顯示「結果待確認」；恢復連線後以該次 `request_id` 查詢本人任務，即使任務已結束也能找到。查無紀錄時顯示仍需人工確認的狀態，不自動重送指令或宣稱成功。待確認識別需在關閉及重新開啟 PWA 後仍可恢復；以使用者為鍵限期保存，避免跨帳號顯示。`navigator.onLine` 僅作提示，實際狀態以 API 結果為準。
5. 更新：Service Worker 有可辨識的快取版本，啟用時只清除自己建立的舊快取；`/sw.js`、manifest、離線頁設定為重新驗證，避免部署後長期卡住舊版。更新中的開啟頁面不可被強制中斷操作。
6. 瀏覽器差異：以瀏覽器內建安裝入口為主；一般使用者介面提供簡短「如何安裝」說明，包含 iOS 加入主畫面，不依賴 `beforeinstallprompt` 作為唯一安裝入口。安裝後須驗證 Email 與 LINE 登入能回到 PWA。
7. 離線登出：明確離線時阻止登出並說明需恢復連線；若登出請求送出後失去回應，標示結果待確認，恢復連線後查證登入狀態。不能假稱登出成功。確認登出後清除待確認請求識別。

## 實作工作項目（依序）

### Task 1: 公開資產與註冊

- 檔案：使用已建立的 `public/icons/pwa-icon.svg`、`public/icons/icon-192.png`、`public/icons/icon-512.png`、`public/icons/apple-touch-icon.png`；新增 `public/manifest.webmanifest`、`public/offline.html`、`public/sw.js`；修改 `resources/views/app.blade.php`、`resources/js/app.jsx`，並在一般使用者介面加入安裝說明入口。
- 先寫 Service Worker 測試，覆蓋「離線文件導覽回離線頁」「API 與 Inertia 請求直通網路」「POST 不被佇列化」「HTTP 錯誤回應不被離線頁取代」。可用 Node 內建測試工具與模擬的 Service Worker 環境，避免引入完整瀏覽器測試框架只為測一個 worker。
- 實作 manifest、可供正式部署使用的圖示、離線頁與 worker；只在支援 Service Worker 的安全來源註冊，註冊失敗不阻斷網站。
- 檢查 `npm run build`，在本機 Nginx/Laravel 來源確認 manifest、圖示、`/sw.js`、`/offline.html` 的狀態碼與 MIME 類型；瀏覽器安裝稽核不得缺必要欄位。

### Task 2: 斷線中的控制體驗

- 檔案：修改 `routes/api.php`、`app/Http/Controllers/ButtonActionController.php`，新增登入者專用 `GET /api/button-actions/request/{requestId}`（靜態 `request` 路由須排在 `/{buttonActionJob}` 之前）。只以目前使用者的 `user_id` 加 `request_id` 查詢，找到則回傳既有 `jobPayload`，查無則回 404；不觸發設備指令。新增對應的 `tests/Feature/ButtonFeatureTest.php` 測試，覆蓋已完成任務仍可查、跨帳號不可查與查無紀錄。
- 檔案：修改 `resources/js/pages/Buttons/Index.jsx`、`resources/js/layouts/AppLayout.jsx`；視需要在 `resources/js/lib/` 新增集中處理斷線、限期保存待確認識別與不確定結果的小模組。待確認識別只存 `request_id`、使用者 `public_id`、建立時間；保存期限 24 小時，登入者變更、成功查證、確認登出或逾期時清除。
- 測試涵蓋：按鈕資料初次載入失敗、輪詢失敗、按鈕 POST 無回應、重新開啟後以 `request_id` 查詢已完成任務、查無紀錄、離線登出、不同帳號不重現待確認資訊。測試應驗證使用者看得到的狀態與沒有自動重送。

### Task 3: 部署與驗收

- 檔案：修改 `nginx.d/default.conf` 處理 PWA 中繼檔快取標頭；在 README 或部署文件新增 HTTPS、安裝、更新、離線測試方式。若實際正式部署另有反向代理/CDN，須在該層套用等價規則。
- **本機程式驗收**：執行 Service Worker 測試、`npm run build`、既有 PHP 測試與 `git diff --check`；以 localhost 驗證 manifest、圖示、worker、離線頁狀態碼、MIME 類型與快取標頭。這只代表本機通過。
- **實際 HTTPS 驗收（最終完成門檻）**：取得實際部署網址與反向代理/CDN 配置後，在桌面 Chrome/Edge、Android Chrome、iOS Safari 完成安裝或加入主畫面。三類平台都檢查從圖示開 `/buttons`、Email 與 LINE 登入回到 PWA、深連結、離線新開的靜態頁、已開頁停用控制與過期提示、POST 結果不明後重新開啟仍可查證、離線登出提示、帳號切換不顯示前一人的資料，以及部署新版後取得新 worker/資產。各平台記錄實測結果；本機建置不能替代此門檻。

## 已確認決策

1. 採路線 B；不提供個人資料離線副本或背景重送。
2. 目標是一般使用者；安裝後入口 `/buttons`；管理後台所有請求直通網路，不納入 PWA 驗收。
3. 名稱沿用 Button Control Center；以現有介面主色製作圖示。現有 favicon 為空檔，已另製作圖示草案。
4. 桌面 Chrome/Edge、Android Chrome、iOS Safari 都須安裝與驗收；一般使用者介面提供安裝說明。
5. POST 回應遺失後以新增唯讀 API 依 `request_id` 查證；待確認識別跨重新開啟保留，帳號隔離並限期清除。
6. 斷線中已顯示資料保留但標示過期、停用修改；離線登出須告知無法完成。
7. 安裝後 Email 與 LINE 登入都列入驗收；實際 HTTPS 三平台驗收通過才是最終完成。

## 驗收界線

本規劃依目前工作樹和官方 PWA 文件制定；除圖示草案外，尚未安裝依賴、修改 PWA 功能、執行建置、啟動容器或做瀏覽器實測。`AGENTS.md`、`docker/ci.Dockerfile*` 是工作樹原有未追蹤檔，實作時應保留，勿納入無關提交。
